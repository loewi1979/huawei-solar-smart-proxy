# Huawei Solar Smart Proxy 1.0

Serve Home Assistant, Victron Venus OS, or both from one serialized Huawei
SUN2000 / SDongle Modbus connection, while keeping FusionSolar connected.

## Included

- SQLite WAL caching with per-register freshness checks across Fast/Slow groups,
  restart persistence and recovery after upstream connection loss.
- Prioritized Fast/Slow polling and an M1 + Huawei Smartmeter profile without
  periodic Huawei battery polling; daily yield refreshes every five minutes.
- Home Assistant support through wlcrs/huawei_solar, including discovery and
  explicit write mode for supported inverter controls.
- MQTT publishing specifically for mr-manuel/venus-os_dbus-mqtt-pv, using an
  embedded authenticated broker or an external broker. Measured phase V/A/Hz
  and opt-in, labelled phase-power estimates; no fabricated phase PF/energy.
- Web dashboard, validated YAML editing, backup/restore and rollback, plus
  configurable web authentication.
- Rolling acquisition medians over 100 intervals per unit/group. Fresh Fast
  groups suggest an HA interval of floor(median / 2), minimum one second.
  Recommendations do not change HA settings automatically.
- Linux/LXC and Docker instructions, configuration examples, systemd unit,
  register/profile documentation and measured SDongle performance.

## Downloads and installation

Download the Linux amd64 or arm64 archive and verify it against `SHA256SUMS`.
Each archive contains the compiled `huawei-solar-proxy` executable and the source,
configuration examples, service files and documentation. Go is not required to
run the compiled executable. Follow the README for service configuration and
installation; the source-build command can be skipped when using this binary.

Default ports: Modbus **1502**, web **8080**, embedded MQTT **1883**.
Public YAML examples start on loopback with writes and MQTT disabled.
Configure your own inverter address, listener bindings and credentials.
Retain the existing configuration when updating, validate it with
`-check-config`, then restart the service. No HA/GX settings are migrated.

## Validation and operational notes

Automated coverage includes cache freshness/persistence, Modbus reconnects,
write/login policy, MQTT scaling/estimates, broker ACLs, stale-data silence,
configuration rollback and dashboard cadence statistics. CI runs Linux race
tests, vet, vulnerability scanning, receiver fixtures and a Docker smoke test.

Daytime hardware observations with HA connected completed 1,320 cached reads
and 331 MQTT messages without failed test reads or MQTT reconnects. Inverter
and meter acquisition medians were approximately 4.5 seconds with the 2-second
profile; intermittent upstream SDongle timeouts were recorded. The operator
confirmed inverter on/off and both power-derating controls through HA, plus
continuous FusionSolar operation. Details and hardware identifiers are in the
README and polling-profile documentation.

The stock Victron receiver requires a nonzero timeout to stop holding values
after message loss. It also has phase-field limitations documented in
`docs/VICTRON.md`; the companion patch is separate and is not installed on a GX
automatically. MQTT silence alone is not an immediate Victron freshness signal.
